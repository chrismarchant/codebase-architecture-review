Spec: SS00 §5.1, §5.4, §6, §8.7, §10 (API side), §11; ADR-003, ADR-008, ADR-009. Depends on C1 (job store, artifact stores, crypto, logger) and H1 (vendored libraries, OpenAPI). May run in parallel with C4; the comparison module reads only published artifacts.

## Requirements

1. **Server** (`hono` + `@hono/node-server`): `createApp(deps)` returns a Hono app for tests; `main.ts` wires env, db (`createPgDb` or PGlite when `DATABASE_URL` is unset and `NODE_ENV!=='production'`), migrations, artifact store, logger, reconciler, and listens on `PORT`. Security headers on every response: CSP from SS00 §5.4 with a per-request nonce, `X-Content-Type-Options: nosniff`, `Referrer-Policy: no-referrer`, `X-Frame-Options: DENY`, `Cache-Control: no-store` on API responses. No CORS headers. Request bodies limited to 256 KiB. Structured request log (method, path, status, ms, principal id) without query strings or headers.
2. **Auth** (core `auth/`): bootstrap principals from `AUTH_BOOTSTRAP_KEYS` (`name:ar_key;…`), storing only hashes; `authenticate(req)` accepting `Authorization: Bearer ar_…` or the `ar_session` cookie; `POST /login` (form) exchanges a key for a session cookie (HttpOnly, Secure when `COOKIE_SECURE`, SameSite=Strict, Path=/); `POST /logout`. Rate limit per principal on `POST` routes using the `rate_limits` table (fixed 60 s windows). Every scan-scoped route resolves the job with `getForPrincipal` and returns 404 when absent.
3. **Routes** exactly as SS00 §6 (validate bodies with the contracts; 422 on validation failure; error envelope everywhere). `POST /v1/scans`: strip `repository.token` from the stored request; seal it with `RETRIEVAL_KEK` (fail with 500 `kek_missing` if a token is given and no KEK is configured); compute `optionsHash`; clamp budgets to `BUDGET_CEILING_*`; `Idempotency-Key` handling incl. 409 on body mismatch (compare canonical JSON of the stored request); `reuseExisting` lookup when `sha` is given; then create the job, respond 202, and fire the wake asynchronously (never block the response on the wake). `GET /v1/scans/:id` composes `Scan` from the row and, when published, from the manifest (cached in memory by `(scanId, publishedAttempt)` for 60 s). `GET /v1/scans/:id/events` streams `job_events` as SSE with `id:` = seq, supports `Last-Event-ID`, polls the table every 2 s while the client is connected and ends when the job is terminal. Artifact routes resolve paths only through the manifest (`artifacts[].path`), never from the request to the store directly; stream from the store with the manifest's `contentType` and `Content-Length`; `Content-Disposition: attachment` for `bundle.tar.gz`.
4. **Wake client + reconciler** (`src/wake.ts`, `src/reconciler.ts`): `wakeRunner(scanId)` POSTs `{ scanId, nonce, ts }` with header `X-Wake-Token: <HMAC>` to `RUNNER_INTERNAL_URL + '/internal/wake'`, retries per `WAKE_RETRY_DELAYS_MS`, logs each attempt to `wake_log`; tolerate 502/503 as retryable. Reconciler: `start()` arms a timer only when `listNeedingWake(60s)` or `listExpiredLeases(LEASE_TTL_MS*3)` returns rows, interval doubling from `RECONCILE_MIN_INTERVAL_MS` to `RECONCILE_MAX_INTERVAL_MS`, and **disarms when both lists are empty** (so the API can sleep); `tick()` is exported and callable from `POST /internal/reconcile` (admin principal only); a tick re-wakes, requeues or fails expired jobs via `requeueOrFailExpired`, and deletes unpublished attempt prefixes older than 24 h (bounded by `RECONCILE_BATCH`/`RETENTION_BATCH`). Also runs the retention sweep when the last sweep was > 24 h ago (keep `last_sweep` in memory; it is fine to repeat after restart).
5. **Hosted viewer**: `GET /v1/scans/:id/viewer/` reads upstream `viewer.html` via `upstream.upstreamViewerHtmlPath()` once (cache), then per request: replace the two jsDelivr `<script src>` tags with `/static/vendor/dagre.min.js` and `/static/vendor/marked.umd.js`, remove the Google Fonts `<link>`, insert `<script nonce src="/static/vendor/purify.min.js">` and a nonce'd inline bootstrap script that sets `window.__projectName`, `window.__ommApiBase = '/v1/scans/<id>/viewer-api'`, `window.__ommSanitizeHtml = (h) => DOMPurify.sanitize(h, {USE_PROFILES:{html:true}})`, and add the nonce to the module script tag. Serve `/static/vendor/*` from disk with immutable caching. `GET /v1/scans/:id/viewer-api/api/*` implements the upstream API shapes by reading the published `.omm` tree: on first access per `(scanId, publishedAttempt)` download the `omm/` prefix into a local cache dir (`ARTIFACT_FS_ROOT`-style temp dir, bounded to 50 scans LRU), then call the upstream store functions with `cwd` = that dir (`listClasses`, `showClass`, `readMeta`, `readField`, `listNodes`, `showNode`, `getIncomingRefs`, `getOutgoingRefs`, `diffMermaid`). `GET …/viewer-api/events` returns an SSE stream that sends `data: connected` and nothing else. Upstream's `Access-Control-Allow-Origin: *` is not emitted.
6. **Upstream viewer hooks** (ADR-003): (a) `const api = p => fetch((window.__ommApiBase||'') + p)…` and `new EventSource((window.__ommApiBase||'') + '/events')`; (b) `const md=t=>t?(window.__ommSanitizeHtml||(h=>h))(marked.parse(t)):''`; (c) remove every `onclick="…"` attribute (header buttons, mobile nav/overlay, `.sb-ref` spans, and the generated `<g class="grp-node"|"reg-node" … onclick=…>` SVG groups) and replace them with `data-action="zoomIn|zoomOut|resetView|toggleTheme|closeSidebar|toggleMobileNav"` / `data-open="<scopedId>"` attributes and **one** delegated `click` listener registered in the existing module script that calls the same functions (`event.stopPropagation()` preserved for node groups). Escape the id with `esc()` wherever upstream did not. Keep everything else byte-identical. `service/test/parity/viewer-hooks.test.ts` asserts: no `onclick=` in the file, the three hooks are present, and the upstream test suite still passes (spawn `npm test` at the root).
7. **Web UI** (server-rendered HTML with the nonce'd CSP; no framework; minimal CSS in `static/app.css`): `/login`, `/scans` (list with status badges and a submit form: url, ref or sha, optional token, language, budgets), `/scans/:id` (progress, stage, perspectives, events via SSE, coverage badge `complete/partial`, links to viewer, artifacts, bundle download, and `review.md` rendered **client side** exactly like the viewer does — the page embeds the Markdown as a JSON string in a nonce'd script and renders it with the vendored `marked` + DOMPurify; nothing is sanitized or rendered on the server), `/scans/:id/compare` (pick another published scan → POST `/v1/comparisons` → render result).
8. **Comparisons** (core `comparison/compare.ts`): `compareScans(base: {architecture, coverage, evidence, ommTree}, head: {...}) → Comparison` using component ids for added/removed, field-by-field for changed, upstream `diffMermaid` for diagrams, relationship ids for edges. API: `POST /v1/comparisons` validates ownership and `succeeded` status of both, computes synchronously (artifacts are small), stores `comparison.json` in the artifact store under `comparisons/<id>/`, inserts the row; `GET /v1/comparisons/:id` returns the record; `GET /v1/comparisons/:id/result` returns the JSON.

## Tests (minimum)

- `auth.test.ts`: bootstrap; bearer ok; bad key 401; session login/logout; cookie flags (A2).
- `authorization.test.ts`: principal B gets 404 on A's scan, artifacts, viewer, viewer-api, events, cancel, comparison (A2).
- `scans.test.ts`: submit → 202 + queued; validation 422; idempotency replay (200 + header) and conflict 409; token never appears in the stored row or any response; budgets clamped; cancel semantics; events SSE with Last-Event-ID (A7).
- `artifacts.test.ts`: seed a published job (write a manifest + files into the fs store and set the row via the job store with a fence) → index, download, 404 for a path not in the manifest even if the object exists.
- `viewer.test.ts`: served HTML has CSP with nonce, no `cdn.jsdelivr.net`, no `fonts.googleapis.com`, no `onclick=`, contains the three hook values; viewer-api responses equal upstream `handleApi` output on the same tree (import upstream `handleApi` and drive it with a fake req/res); Markdown containing `<img onerror>` and `<script>` is sanitized client side — assert the sanitizer hook is wired and add a jsdom-free check that `purify.min.js` is served (A12).
- `reconciler.test.ts`: timer disarmed with no work; wake retries; expired lease requeued; bounded batch.
- `comparison.test.ts`: two seeded scans → added/removed/changed and diagram diff (A15).
